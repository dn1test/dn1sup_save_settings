# DN1SUP Save Settings

Сохранение параметров SketchUp в zip-архив и восстановление из архива.
Интерфейс: HTML (Vue 3 + Tailwind, Vite singlefile), тёмная/светлая тема.

## Что сохраняется (SketchUp 2024+)

| Путь | Где |
| --- | --- |
| `PrivatePreferences.json` (настройки интерфейса + значения `Sketchup.write_default` — настройки расширений) | `%LOCALAPPDATA%\SketchUp\SketchUp 202x\SketchUp\` |
| `SharedPreferences.json` (системные настройки) | `%APPDATA%\SketchUp\SketchUp 202x\SketchUp\` |
| `Components`, `Materials`, `Plugins`, `Styles`, `Templates` | `%APPDATA%\SketchUp\SketchUp 202x\SketchUp\` |

Проверено на SketchUp 2026: значения `Sketchup.write_default` SketchUp сбрасывает
в `PrivatePreferences.json` (Local) при выходе, а не в SharedPreferences.json —
оба файла архивируются, поэтому настройки расширений попадают в копию.

Состав каждого архива выбирается чекбоксами; для путей показываются размеры.

## Архив

- Имя: `dn1sup_settings_ГГГГ-ММ-ДД_ЧЧММСС.zip` (авто- и импортированные — с префиксом/суффиксом).
- Внутри: `dn1sup_settings_manifest.json` (метаданные: дата, версия SketchUp,
  пользователь, комментарий, состав), `dn1sup_settings_log.txt` (лог архивации)
  + содержимое целей в каталогах `roaming/…` и `local/…`. Пути относительные —
  восстановление работает на другой машине и в другой версии SketchUp.
- Лог архивации (`dn1sup_settings_log.txt`, начиная с v0.3.0): шапка (дата,
  версия SketchUp, пользователь, тип копии, комментарий, состав) + секция на
  каждый путь: источник, число файлов и суммарный размер, построчный список
  файлов с размерами (при очень больших папках список усекается до 10 000
  строк, счётчики остаются точными) + итог. Лог строится по фактическому
  содержимому staging-папки, то есть всегда совпадает с тем, что попало в
  архив. Читается в интерфейсе кнопкой «Лог» у каждой записи истории; в архивах
  старых версий лога нет — окно показывает пояснение.
- Движок zip — встроенный в Windows `tar.exe` (bsdtar, System32); никаких
  сторонних зависимостей. Windows-сборка bsdtar не умеет `-s` (переименование
  записей), поэтому архив собирается из staging-папки с целевой структурой.
- Внутри SketchUp stdout дочерних процессов пуст — манифест и лог читаются
  распаковкой одного файла (`tar -xf архив.zip -C tmp файл`), вывод в
  stdout не используется.

## Хранилище

`%APPDATA%\SketchUp\SketchUp <год>\dn1sup_save_settings\`:

- `backups\` — zip-архивы (папка по умолчанию);
- `history.json` — история сохранений (файл, дата, размер, комментарий, состав);
- `settings.json` — настройки расширения (папка архивов);
- `dn1sup_save_settings.log` — журнал работы и ошибок (см. ниже);
- `pending_restore\` — подготовленная отложенная задача (см. ниже).

Каталог — сосед бэкапируемого `…\SketchUp 202x\SketchUp\`, поэтому архив
не захватывает сам себя. Для тестов путь переопределяется переменными
`DN1SUP_SAVE_SETTINGS_STORE_DIR`, `DN1SUP_SAVE_SETTINGS_ROAMING_ROOT`,
`DN1SUP_SAVE_SETTINGS_LOCAL_ROOT`.

## Журнал работы (v0.6.0)

Файл `dn1sup_save_settings.log` в хранилище расширения — единый журнал
работы и ошибок. Каталог хранилища лежит **вне** папки Plugins, поэтому
журнал переживает полное удаление расширения (обновление, установку `.rbz`
поверх, сброс плагинов). Открывается пунктом меню
**Extensions → DN1SUP → Save Settings → «Открыть папку логов»**.

- Что пишется: баннер сессии SketchUp (версии SketchUp/Ruby/плагина, пути,
  установленные `DN1SUP_SAVE_SETTINGS_*` переменные), загрузка/выгрузка
  расширения, открытие диалога и команды интерфейса, создание/импорт/
  восстановление копий (со временем выполнения), подготовка и результат
  отложенного применения (ошибки PowerShell-helper'а, отработавшего после
  закрытия SketchUp, попадают в журнал следующей сессии), обновление из
  dev-папки, ошибки JS-интерфейса (перехват `window error` /
  `unhandledrejection`) и все перехваченные исключения с backtrace —
  в том числе те места, которые раньше молча проглатывались (недоступен
  tar.exe, повреждённые `settings.json`/`history.json`, ошибки
  ShellExecuteW и т.п.).
- Формат: `ГГГГ-ММ-ДД ЧЧ:ММ:СС.ммм [INFO|WARN|ERROR] сообщение`, UTF-8
  (не-UTF-8 сообщения перекодируются, битые байты заменяются).
- Ротация: при превышении 2 МБ журнал сдвигается в `.1` и `.2`
  (максимум ~6 МБ на диске).
- Запись не может уронить расширение: любая ошибка записи глушится
  (с дублем в консоль Ruby). Модуль журнала загружается первым и не имеет
  зависимостей — ошибки загрузки остальных модулей и регистрации попадают
  в журнал. Папка журнала для тестов переопределяется переменной
  `DN1SUP_SAVE_SETTINGS_LOG_DIR`.

## Папка архивов

Место хранения архивов настраивается (кнопка-карандаш у строки «Хранилище»
в интерфейсе):

- заданная папка (`settings.json`, ключ `archive_dir`) принимает новые
  резервные копии — быстрые, ручные, автобэкапы и импортированные;
- архивы, созданные до смены папки, остаются доступны: восстановление,
  чтение состава, «показать в папке» и удаление ищут файл по имени сначала
  в текущей папке, затем в стандартной;
- история сохранений всегда хранится в хранилище расширения и от папки
  архивов не зависит;
- Ruby отклоняет выбор папки внутри архивируемых каталогов SketchUp
  (Materials, Plugins, …) — иначе архив захватывал бы сам себя; относительные
  пути (`C:` без каталога, `relative\path`) тоже отклоняются;
- сброс на стандартную папку — кнопкой «Сбросить» в окне «Папка архивов».

## Возможности интерфейса

- Создание резервной копии с комментарием и выбором состава.
- Папка архивов: выбор каталога для хранения резервных копий, сброс на
  стандартную; архивы из прежней папки остаются доступны.
- История сохранений с датами: бейджи «Ручная / Быстрая / Авто / Импорт»,
  размер, версия SketchUp, состав, просмотр лога архивации («Лог»).
- Восстановление с подтверждением: состав архива из манифеста, опция
  «сначала сохранить текущие настройки» (автобэкап, по умолчанию включена).
- Отложенное применение файлов настроек (v0.4.0): PrivatePreferences.json и
  SharedPreferences.json применяются автоматически сразу после закрытия
  SketchUp (см. ниже), каталоги — сразу, после перезапуска SketchUp.
- Сброс к заводским настройкам (v0.5.0): кнопки внизу окна — «Сброс
  интерфейса» (удаление PrivatePreferences.json) и «Сброс плагинов» (очистка
  папки Plugins). Перед сбросом принудительно создаётся резервная копия;
  применение — отложенное, сразу после закрытия SketchUp.
- Импорт zip-архива с диска (с манифестом dn1sup), удаление архивов,
  открытие папки хранилища.

## Отложенное применение файлов настроек

SketchUp держит настройки в памяти и перезаписывает оба JSON-файла при выходе
(и по отдельным событиям сессии), поэтому восстановить их «вживую» в
запущенном SketchUp нельзя — при закрытии он затрёт восстановленное своим
состоянием. Поэтому:

- при подтверждении восстановления файлы настроек распаковываются в папку
  `pending_restore` хранилища и запускается отсоединённый PowerShell-скрипт
  (`apply_restore.ps1`, только Windows PowerShell 5.1, без зависимостей);
- скрипт опросом `Get-Process` дожидается закрытия процесса SketchUp
  (не дольше суток), делает страховочную копию только что сброшенных
  SketchUp'ом файлов в `pre_restore_<штамп>/`, применяет файлы из архива и
  пишет `result.txt`;
- по галочке «Запустить SketchUp после применения» (запоминается)
  SketchUp стартует автоматически уже с восстановленными настройками;
- пока SketchUp открыт, подготовленное восстановление можно отменить —
  кнопка «Отменить» в баннере (скрипт без `pending.json` ничего не меняет);
- после перезапуска интерфейс показывает результат (`result.txt` читается
  с учётом BOM); задача прошлой сессии без результата помечается как
  «helper не сработал» (например, заблокирован антивирусом/политикой);
- каталоги (Components, Materials, Plugins, Styles, Templates) применяются
  сразу, как и раньше — они не перезаписываются SketchUp'ом при выходе;
- у файлов настроек в списке путей показывается время последней записи
  на диск («на диске изменён …»): на диске может быть состояние не текущей
  сессии.

## Сброс к заводским настройкам (v0.5.0)

Кнопки в самом низу окна диалога:

- **Сброс интерфейса** — отложенное удаление `PrivatePreferences.json`:
  после закрытия SketchUp файл удаляется, и при следующем запуске вид
  SketchUp (панели инструментов, окна, раскладка) создаётся заново
  с заводскими значениями;
- **Сброс плагинов** — отложенная очистка папки `Plugins`: после закрытия
  SketchUp удаляется всё её содержимое (все установленные расширения,
  включая само расширение Save Settings), сам каталог остаётся.

Порядок работы:

1. подтверждение в окне с предупреждением (что будет удалено и когда
   применится);
2. Ruby **принудительно** создаёт резервную копию сбрасываемого пути
   (kind `auto`, комментарий «Автоматически перед сбросом: …») — если копию
   создать не удалось, сброс не выполняется;
3. готовится отложенная задача (`pending_restore`, действие `delete_file`
   или `clear_dir` по виду цели) и запускается тот же helper-скрипт;
4. сразу после закрытия SketchUp файл удаляется / каталог очищается,
   результат попадает в `result.txt` и показывается при следующем запуске;
   по галочке «Запустить SketchUp после применения» SketchUp стартует
   автоматически.

Вернуть состояние можно восстановлением из созданной перед сбросом копии
(для плагинов — сначала вернуть само расширение: установить `.rbz` из `dist/`
или распаковать копию в папку `Plugins` вручную). Пока SketchUp открыт,
подготовленный сброс отменяется кнопкой «Отменить» в баннере.

## Разработка

```
frontend/          ← исходники UI (Vue 3 + Vite + Tailwind); npm install && npm run build
dn1sup_save_settings/
  dn1sup_save_settings.rb    ← регистратор (корень Plugins)
  dn1sup_save_settings/      ← пакет: main, dialog, log, paths, archiver, backup,
                               restorer, history_store, store, settings,
                               win_shell, ui/, test/
update_from_dev.rb ← ruby update_from_dev.rb: копия в Plugins + hot reload (порт 9877)
```

Тесты: `ruby test/run_all.rb` из пакета или `ext_test` в живом SketchUp.

Задача расширения зарегистрирована в monorepo `dn1sup_extensions`
(`registry.json`, `tools/pack.rb`).
